## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A stable C API next to the Rust one so C, C++, Swift, Go, Python, Zig and other embedders can use the engine (QuickJS popularity owes much to its C embedding). Separate crate, header generated by cbindgen or hand-written, opaque handles matching the handle-based host interface (ADR 0006), ABI and versioning policy, ownership and error rules documented. Unsafe confined to this crate. Model: Opus.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A C header and static and dynamic libraries expose realm creation, script and module evaluation, values and handles, host functions and host classes, jobs and timers, limits and fuel, and bytecode load and save
- [x] #2 A C test suite and a small non-Rust example (for example Swift or Python via ctypes) run in CI; a leak and sanitizer run is clean
- [x] #3 An ABI and versioning policy is documented and enforced by a header-drift check
- [x] #4 No panic can escape or abort the host: clippy denies unwrap, expect, panic, indexing and slicing in the C API crate; every extern function is wrapped in catch_unwind and maps a panic to an error result; the crate builds with panic=unwind; a fault-injection test forces panics at each entry point, and malformed input, invalid handles, double frees and use after teardown all return errors, with the process surviving and a poisoned handle failing safely
- [x] #5 Before the C API is stable, every reachable panic in the engine core public paths is audited: fuzzing the engine interface with arbitrary scripts, bytecode and handle sequences finds no panic, and any found are fixed in the engine

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. New crate crates/agnijs-capi (cdylib + staticlib + rlib) over agnijs-engine-api and agnijs-js-vm; unsafe confined there, every unsafe block documented; clippy denies unwrap/expect/panic/indexing/slicing/unreachable/todo/arithmetic side effects/truncating casts.
2. Everything the host holds is a generation-checked u64 id (engine, realm, class, value, buffer, sink): engines live in a thread-local registry (wrong thread is an error, not a race), value handles carry an engine tag, slots retire instead of wrapping generations. No Rust allocation is freed by C or the reverse: outputs are buffer handles or copies into caller memory.
3. Every extern fn runs under catch_unwind; a caught panic returns AGNIJS_ERR_PANIC, poisons the engine, and teardown stays safe. Host callbacks are extern C-unwind and run under catch_unwind too. Reentrancy from host callbacks goes through a lease stack (one live &mut at a time), depth-limited; calls from hooks that have no engine return AGNIJS_ERR_BUSY. Versioned structs (struct_size, trailing bytes must be zero). panic=abort refused at compile time.
4. Surface: realms, scripts, modules with host resolve/load hooks (source, JSON, bytecode), values in and out (UTF-8 and lossless UTF-16), properties, calls and construct, host functions and classes with finalizers, exceptions with name, message and stack, promise state and job pumping, memory limit and usage, interrupt hook plus a thread-safe interrupt request, bytecode save and load.
5. cbindgen header checked in with a CI drift check; ABI and versioning policy in docs/c-api.md and an ADR.
6. Tests: Rust unit and integration tests, fault injection at every entry point (feature fault-injection), hostile-input suite, bounded fuzz and differential test of the FFI surface (random call sequences, mutated scripts and bytecode), C test program, C and C++ examples via CMake in CI on Linux, Windows and macOS, ASan and LSan run of the C test on Linux, Miri on the handle and validation tests, the crate in the GC-stress job.
7. Fix any engine panic the fuzzing finds; run workspace tests and default test262 once at the end.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Maintainer requirement (2026-11-08): a panic must never cross, or crash the host through, the C API. The y-crdt FFI layer (yffi) panics on Rust errors and takes down the hosting application; that is unacceptable here. Rules: no unwrap, expect, panic, unchecked indexing or slicing, unreachable or todo in the C API crate (denied by clippy lints in CI); every extern fn body runs under catch_unwind and returns an error code or error handle on a panic; the C API crate builds with panic=unwind (never panic=abort, which would abort the host); a caught panic poisons that engine or realm handle, later calls return a clear error, and teardown stays safe; allocation failure and stack exhaustion are reported as errors within the engine's memory and stack limits, and any remaining abort path is documented; callbacks into host C code are treated as untrusted. Model: Opus.

2026-11-10, done (commits 470e7bc, 8846650, 0602477, 072e5a9, e92e7ec, c77c7ce on main):

Surface:
- crates/agnijs-capi, built as cdylib and staticlib, with 65 exported functions plus a fault-injection hook.
- The header include/agnijs.h is generated by cbindgen and checked in; CI checks it for drift.
- Covered: realms; scripts; modules with resolve, load and import.meta hooks (source, JSON or bytecode); values (UTF-8 and lossless UTF-16, bigint, symbol, error); properties by name or value; call and construct; host functions and host classes with finalizers; exceptions with name, message, stack and frame count; promise state and job pumping; the rejection hook; memory limit and usage; GC; the interrupt hook and a cross-thread interrupt request; the clock hook; bytecode save and load.

Safety:
- Every handle is a u64 id (tag, generation, index); slots retire rather than wrap.
- Engines live in a thread-local registry; a call from another thread returns WRONG_THREAD.
- Reentrancy goes through a lease stack capped by max_reentrancy.
- Every export and every callback runs under catch_unwind; a caught panic returns PANIC and poisons the engine.
- Clippy denies unwrap, expect, panic, indexing, slicing, arithmetic and truncating casts; panic=abort is refused at compile time.
- Versioned structs: struct_size must be at least the known size, and trailing bytes must be zero.

Engine change, found by the hostile suite:
- Deep nesting (in source, JSON, flat, proxies, bound functions, native reentry, regex) overflowed the host thread's stack.
- Added an optional native stack budget (agnijs_js_regex::stack, re-exported by the parser). It is checked in the parser, regex, compiler analysis and codegen, and VM recursion.
- The C API sets one per call: stack_budget, default 512 KiB, minimum 64 KiB, plus 256 KiB of headroom.
- With no budget nothing changes: test262 stays at 42231/42231, 0 regressions.

Tests:
- basics: 21. hostile: 15, including a depth sweep up to 40000 on a 1 MiB thread. fault_injection: 3, with a panic forced at every entry point. Lib: 5 miri_ tests (the handle table and every raw-pointer helper).
- fuzz.rs: seeded and bounded. It runs random call sequences over live, freed, foreign and forged ids and random bytes; mutated scripts compared against the Rust engine; invalid UTF-8 source; mutated bytecode.
  - Checks: no PANIC status, only known statuses, and the host handle count equals what the test owns.
  - Result: clean at 15x across 4 seeds (about 430k calls, 24k scripts, 36k bytecode images). CI runs it at 10x.
- C: capi_test.c, examples/timers.c (event loop, setTimeout, virtual clock) and examples/classes.cpp (RAII wrapper, host class, JS constructor shim). CMake/ctest builds each against the static and the shared library on Linux, Windows and macOS.
- CI also runs the C test under ASan and LSan, Miri on the miri_ tests, the capi suites in the gc-stress job, and clippy with -D warnings.

Docs: docs/c-api.md (ABI and versioning policy, ownership, threads, reentrancy, the stack budget, remaining abort paths) and ADR 0021.

AC1 is left unchecked because of fuel only: the engine has no instruction-count fuel, so the C API has none. Running time is bounded with the interrupt hook (count- or clock-based) and agnijs_engine_request_interrupt. Everything else in AC1 is delivered, including timers: the host drives them with run_jobs and the clock hook, as timers.c shows.

Known limits:
- Host functions are not constructors in ABI 1.0, so new_target is always 0; documented, with a JS wrapper as the workaround.
- System OOM still aborts (the Rust allocator).
- A thread with less free stack than budget plus headroom can still overflow.
- The macOS static link libraries are as listed in c/CMakeLists.txt; CI is green with them.
