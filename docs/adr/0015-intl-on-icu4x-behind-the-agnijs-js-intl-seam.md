# 15. Intl is ICU4X behind the agnijs-js-intl seam, with bundled CLDR tables and spec-shaped workarounds

Date: 2026-11-08

## Status

Accepted

## Context

M6 adds ECMA-402 (`Intl`) to the AgniJS engine: Collator, DateTimeFormat, DisplayNames, ListFormat, Locale, NumberFormat, PluralRules, RelativeTimeFormat, Segmenter, `Intl.supportedValuesOf` and the locale-sensitive methods of String, Number, BigInt, Date, Array and the typed arrays. The engine must stay pure Rust with no platform-specific code (ADR 0006), the host supplies the default locale and time zone (ADR 0014 for the clock), and the milestone is judged by test262's `intl402` suite with every exclusion carrying a reason.

ICU4X (2.4) is the only pure-Rust implementation of CLDR behaviour with the coverage ECMA-402 needs, but its API does not line up with ECMA-402 one-to-one:

- it has no flexible day periods (CLDR pattern character `B`), no `DurationFormat` data, and its baked data omits a few locales test262 reaches for (`ln`, `gv`) and some tailorings (German `search` collation);
- its date-time field sets cannot express every ECMA-402 component bag (hour-less bags with a minute, `hourCycle: "h24"`, a weekday whose width differs from the month's, `dateStyle: "short"` two-digit years);
- its interval formatter returns runs, not ECMA-402 parts with `source` annotations, and may pick a different skeleton than the two single formats (Chinese calendar);
- some symbol data is missing (`en-u-nu-arab` decimal symbols) and likely-subtag expansion leaves `und-<region>` unchanged;
- it does not canonicalize ECMA-402 keyword values (`"true"` → `""`, aliases) or tokenize tags the way `IsStructurallyValidLanguageTag` requires.

## Decision

**ICU4X sits behind the `agnijs-js-intl` crate.** The VM's `builtins/intl/*` modules do the ECMA-402 abstract operations (option reading order, `ResolveLocale`, `SupportedLocales`, record shapes, error ordering) and call the seam for everything locale-sensitive. The seam exposes plain Rust types (strings, parts with `kind`/`value`/`source`, plural categories) and never leaks ICU4X types, so a future ICU4X upgrade or replacement touches one crate. The seam owns its own BCP 47 tokenizer and canonicalizer, keyword-value canonicalization, and availability check (a tag is available only when its subtag count matches what ICU4X parsed, so `de-x` is rejected while `de-x-u-co-phonebk` is not).

**Tables ICU4X lacks are bundled, generated from upstream data.** `src/cldr_tables.rs` (unit display names, currency and number data for a configured locale list: en, en-GB, en-IN, de, de-CH, ja, ko, zh, zh-Hant, fr, es, it, pt, pt-PT, ru, ar, hi, with fallback to the parent then to `en`) is generated by `tools/gen-cldr.js` from the cldr-json packages; `src/tables.rs` (numbering-system digits, sanctioned units, IANA zone1970 region→zones) by `tools/gen-tables.js` from the test262 harness tables and `zone1970.tab`. Both are Node scripts taking the download directory as their argument. ICU4X's own data is the crate-default compiled set; trimming it to an application's locale list through `icu4x-datagen` is deliberately left as a follow-up, and that is why the milestone's first acceptance criterion stays open.

**Spec-shaped behaviour is recovered in the seam, not in the VM:**

- hour-less component bags and `h24` are formatted with a synthesized `hc-h23` hour that `fix_parts` strips (or rewrites midnight to `24`) along with the literal that follows it;
- a weekday whose width differs from the month's comes from a second formatter built from the same field set at the weekday's length, taking only the weekday part (so the format form `Sa.` is used, not the stand-alone `Sa`);
- `dateStyle: "short"` detects the two-digit year from the epoch-0 output and truncates the year part, dropping the era;
- `formatRangeToParts` aligns ICU4X's interval runs against the two single formats (start runs by prefix, end runs by suffix, with shared prefixes and suffixes when the interval is collapsed); when the leftover text is not plain punctuation the seam joins the two single formats with `U+2009 – U+2009` instead of guessing;
- `arab`/`arabext` symbols come from `ar`/`fa` when the requested locale has none, `und` likely-subtag expansion fills the root with `en`/`Latn`/`US`, `hour12: true` picks `h11` only for Japan, a currency with no localized name falls back to its code, and `PluralRules` with a compact or scientific notation selects on the formatted significand and exponent;
- negative zero in `RelativeTimeFormat` with `numeric: "auto"` is `now`/`today`, and `U+2212` is not an offset sign.

**The legacy constructor fallback symbol is per realm** (`Realm::intl_fallback`, rooted by the GC), not a well-known symbol, since ECMA-402 defines it per realm.

**intl402 is reported separately.** The runner's `--only-intl402` flag runs `test/intl402/` against `baselines/agnijs-intl402.json`; the main baseline keeps excluding the suite, so the language suite's zero-regression gate is unaffected by Intl data churn. CI runs both.

## Consequences

- intl402: 981 pass, 0 fail, with 12 reasoned exclusions (8 flexible-day-period tests, `DurationFormat` (post-ES2025), `Collator/usage-de` (no German search tailoring), `PluralRules` category order (no `gv` data), one `numbering-system` test whose expectation hard-codes U+0020 where CLDR 46 has U+202F). The main suite stays at 42225/42225.
- The bundled unit and currency names cover 17 locales; other locales get the parent's or English names. Widening the list is a regeneration, not a code change.
- ICU4X data is the full default set, so binary size is not yet tuned per application. A datagen-built custom baked-data crate behind the same seam is the planned follow-up. (Done: see the addendum.)
- The range-part alignment is heuristic by construction. Its failure mode is the manual join, which is always a correct ECMA-402 result, never garbled parts.
- An ICU4X upgrade that adds flexible day periods or German search tailoring removes exclusions without touching the VM.

## Addendum (TASK-103.5, 2026-11-10): Intl is a cargo feature, and ICU4X data can be trimmed per app

**`intl` is a default feature of `agnijs-js-vm`.** With it off, the VM does not compile `builtins/intl`, there is no `Intl` global, and `agnijs-js-intl` and ICU4X are not linked. The locale-sensitive methods then take the behaviour ECMA-262 alone specifies:

- Number and BigInt `toLocaleString` are `toString`.
- Date `toLocaleString`, `toLocaleDateString` and `toLocaleTimeString` are `toString`, `toDateString` and `toTimeString`.
- `localeCompare` compares the NFC forms by code point, so canonically equivalent strings are equal.
- `toLocale{Upper,Lower}Case` use the root case mapping and do not read the locale list.
- Array and %TypedArray% `toLocaleString` call each element's `toLocaleString` with no arguments.

The main test262 suite passes in full in both builds. The workspace's `agnijs-js-vm` dependency now has no default features, and each member names the engine features it needs.

**Trimmed data uses ICU4X's own mechanism, not a second provider.** When `ICU4X_DATA_DIR` names a directory generated by `icu4x-datagen --format baked`, every ICU4X data crate compiles that data in place of its default set. `tools/gen-icu4x-data.js` wraps datagen for a locale list (or ICU4X's `recommended`, `modern` or `full` sets) and for `--segmenter-models none`. The seam's own provider (`provider.rs`) imports each data macro by name: under a custom data directory every data crate exports every marker's macros, so glob imports would be ambiguous. ICU4X falls back to the root for a locale the data lacks, so a trimmed build never fails: it formats in the default style and leaves the locale out of `supportedLocalesOf`.

**The default stays the crate-default (`recommended`) data**, because `intl402` exercises locales and calendars across that set. Calendars and collations are not trimmed separately. ICU4X keys date data per calendar, but the seam's formatters take any calendar a tag names (`-u-ca-`), so they reference every calendar's markers and the data has to hold them all. Dropping calendars would need a calendar list in the seam, and ECMA-402 requires the calendars `Intl.supportedValuesOf('calendar')` reports.

Consequences:

- Sizes and the recipe are in `docs/binary-size.md`. Intl costs about 16.8 MB of a 20.1 MB stripped native build. One locale with no segmenter models brings that down to about 2.7 MB.
- intl402 stays 981/981 on the crate-default data and on datagen's `recommended` and `modern` sets. The main suite is 42231/42231 without `intl` and with English-only data.
- CI builds the no-Intl and trimmed-data configurations, runs their tests and the main suite against them, and prints the size report.
- The bundled `cldr_tables.rs` (unit and currency names for 17 locales) is not affected by `ICU4X_DATA_DIR`. It is small (a 190 KB source file) and goes away with the `intl` feature.
