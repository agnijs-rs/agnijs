# 10. Precompiled code ships in a versioned container that is rejected on mismatch

Date: 2026-11-08

## Status

Accepted

## Context

The spec (`docs/js-engine-spec.md`, section 3) requires serialisable bytecode so production bundles can ship precompiled code, with a versioned format that is rejected on mismatch. Full serialisation of register bytecode is M7 work, but the engine-interface `compile`/`load` methods exist from M2 and need a wire shape that will not change when M7 lands.

## Decision

- **Container header first, payload second** (`agnijs-js-vm/src/engine.rs`): a `GBLC` magic, the format string (`agnijs-bc-1`), a kind byte (script or module), the script name and then the payload. The header is checked before any payload byte is interpreted, and a mismatch is a version error from `load`, never a crash.
- **M2 payload is the source text.** `compile` produces a container whose payload is the source; `load` recompiles it. This gives the host the final API and error behaviour now, and lets M7 swap the payload for serialised register bytecode behind the same header by bumping the format string.
- **The format string pins the compiler version**, not the engine release: any change to `Instr`, `CodeBlock` or the constant pool encoding changes the string. A container produced by a different compiler is rejected rather than reinterpreted.

## Consequences

- Hosts can integrate precompilation (bundling, caching) against the M2 engine; the only behavioural change in M7 is faster `load`.
- Two format strings will coexist briefly in M7 (source payload and bytecode payload) so caches produced before the switch keep loading; after one release the source payload is removed.
- The container does not carry a checksum; the host's bundle format is responsible for integrity.

## Addendum (M7, 2026-11-08): the bytecode payload

- **Format `agnijs-bc-2` in the shared container.** `compile_script`/`compile_module` now emit the `agnijs-engine-api` bytecode container (`AGJS` magic, NUL-terminated format tag) with the tag `agnijs-bc-2`, so every engine behind the interface rejects every other engine's bytes the same way. The payload is a kind byte (script or module), an FNV-1a 64-bit checksum of the kind byte and the tree, and the serialised `CodeBlock` tree (`agnijs-js-compiler/src/serialize.rs`): instructions, constants, names, nested functions, scopes, handlers, spans and offsets, with strings, UTF-16 constants and the source text each stored once in tables. Inline-cache slots are stored as a count and come back empty.
- **A checksum after all.** The Consequences above said the container carries no checksum. M7 adds one, because the loader now interprets an instruction stream: a flipped byte that still decodes could, for example, turn a constant into a jump and run nonsense, or reach VM invariants (such as `LdaImport` outside a module) that panic. The checksum turns accidental damage into `BytecodeCorrupt` before anything is decoded. It is not a signature: a host loading untrusted bytecode must still authenticate it.
- **The loader verifies what it can check locally.** After the checksum, decoding checks the operand pools: register indices and ranges against the frame size, constant indices and kinds, names, function and scope indices, inline-cache slots, jump targets, handler ranges, spans on character boundaries, offsets per instruction, that each block ends in a terminator, and nesting at most 256 deep. Operands whose validity depends on the runtime context (environment depth and slot, module import slots) are trusted, so the format stays bound to the compiler that wrote it, which the format tag already pins.
- **The legacy source payload still loads for one release.** A `GBLC`/`agnijs-bc-1` container is recompiled from its source as before. It is removed in the next release, as planned above.
- **test262 runs from bytecode as well.** `test262 run --engine agnijs --precompile` sends every harness file, test script and module through `compile_*` and loads the bytes, against the same exclusions and baseline. It runs in CI next to the source run.

## Addendum (M8, 2026-11-08): `agnijs-bc-3` carries statement offsets

- **The tag moves to `agnijs-bc-3`.** M8's debugger (ADR 0017) pauses at statement starts and reports the statement's own source position, not the position of the first instruction's expression. Each block's debug info now holds its statement starts as (instruction index, source offset) pairs, plus the bindings kept in registers as (name, register, instruction range). Both are serialised. The verifier checks that statement indices are ascending and in range, that offsets fall inside the source text, and that locals name valid registers and instruction ranges. Precompiled code therefore pauses, steps and shows locals exactly like code compiled from source.
- **Debug info is packed.** By count, it is most of a block's metadata. Statement starts are stored as LEB128 deltas: the instruction index as an unsigned delta and the source offset zigzag-encoded. Locals are stored as LEB128 (string-table index, register, start, length). The decoder for this section is kept out of line so that the instruction loop compiles as before. On the 900-function `bytecode-load` workload, the payload grows by 5% and loading is about 5 to 10% slower than `agnijs-bc-2` (about 0.25 ms). Decoding the section lazily, only once a debugger attaches, is the next step if that matters.
- **`agnijs-bc-2` payloads are rejected, not migrated.** The payload layout changed, so a `agnijs-bc-2` container fails with the usual format mismatch and the host recompiles from source. That follows the rule above: bytecode is a cache tied to one engine build. M7 shipped no release, so no released artefact carries `agnijs-bc-2`. The `GBLC`/`agnijs-bc-1` source container still loads, as the M7 addendum says.

## Addendum (2026-11-09): the source-payload loader is removed

- **`GBLC` containers are refused.** The M7 addendum kept the M2 source-payload container loading for one release. The repository split (TASK-100.12, ADR 0016) renamed its tag from `gable-bc-1` to `agnijs-bc-1`, so from then on the loader accepted only a tag that no compiler ever wrote, and the containers that M2 builds did write (`gable-bc-1`) were already refused. No release shipped in between. The loader was dead code and is removed: a `GBLC` container now fails with the usual format mismatch, and the host recompiles from source. `agnijs-bc-3` was from then the only format this engine loads.

## Addendum (TASK-100.28, 2026-11-09): `agnijs-bc-4` loads in one pass and decodes debug info lazily

- **The tag moves to `agnijs-bc-4`.** The block layout changed for loading speed (finding 9e of `docs/js-engine-performance-findings.md`): `agnijs-bc-3` payloads are rejected with the usual format mismatch and the host recompiles from source. No release shipped `agnijs-bc-3`.
- **Pools before instructions, one verification pass.** Within a block, everything an instruction can index (constants, names, scopes, the inline-cache and nested-function counts) now comes before the instructions, so each instruction's operands are verified as it is decoded instead of in a second pass over the block; offsets, handlers and the declared function indices are checked as they are read. The nested blocks come last. What is verified is unchanged (the M7 addendum's list).
- **Every count precedes its items, and the loader allocates each pool at its final size.** The previous decoder collected through a `Result` adapter, which reports no size hint, so every pool grew by doubling: vector growth and reallocation were 15% of the load.
- **The debug section is decoded on first use.** The M8 addendum's statement starts and locals are now prefixed by their byte length. Loading skips the section and keeps its bytes (plus a reference to the payload's string table) in the block's `DebugSection`; the first debugger use of that block (stepping, locals, breakpoint resolution, a pause position) decodes and verifies it, and the verdict is kept. Stack traces use the per-instruction offsets and never touch it. A malformed section does not stop the code from running: the debugger then sees that block as having no statement starts or locals, and `DebugSection::get` reports the error. While a debugger is attached, `eval_bytecode` and bytecode module loads verify every block's section at load and refuse the container as `BytecodeCorrupt`, so under a debugger a malformed payload is rejected before anything runs, as before.
- **The checksum hashes 64-bit words.** The payload checksum is still FNV-1a (offset basis, prime, kind byte first), but over little-endian 64-bit words of the tree (the last one zero-padded) followed by the tree's length, instead of over bytes. The byte-serial multiply chain was 8% of the load. Each step multiplies by an odd constant, a bijection on `u64`, so inputs that differ in one word never collide; a flipped byte, a truncation or a moved boundary is still caught before anything is decoded. As before, it is not a signature.

## Addendum (TASK-100.18, 2026-11-09): `agnijs-bc-5` adds named-operand and fused compare-and-branch instructions

- **The tag moves to `agnijs-bc-5`.** `Instr` gained twelve variants (finding 3 of `docs/js-engine-performance-findings.md`): `BinRR`, `BinRI`, `BinAR` and `BinAI` (a binary operator whose operands are two registers, a register and an integer immediate, the accumulator and a register, or the accumulator and an immediate) and `JumpIfCmpRR`, `JumpIfNotCmpRR`, `JumpIfCmpRI`, `JumpIfNotCmpRI`, `JumpIfCmpRA`, `JumpIfNotCmpRA`, `JumpIfCmpAI` and `JumpIfNotCmpAI` (a comparison on the same operand forms fused with the branch on its result). The instruction table changed, so `agnijs-bc-4` payloads are rejected with the usual format mismatch and the host recompiles from source. No release shipped `agnijs-bc-4`.
- **The operator is an operand.** These instructions carry a `BinOp` byte, a bytecode-owned list of the 22 binary operators encoded as its position in that list (like the other fieldless enums), not the parser's `BinaryOp`. `Instr` stays 12 bytes and `pc` an instruction index (ADR 0019 J2); the fused forms with an immediate and an offset are the widest.
- **The verifier checks the operator too.** Besides registers against the frame size and offsets against the block, the fused branches accept only a comparison operator (`BinOp::is_comparison`): an arithmetic operator in a `JumpIfCmp*` is `BytecodeCorrupt`, since the interpreter's branch decision is defined only for comparisons. The `Not` forms branch when the comparison is false, which is not the opposite comparison (NaN), so both polarities are distinct instructions rather than a swapped operator.

## Addendum (TASK-100.15, 2026-11-09): `agnijs-bc-6` keeps the lone surrogates of eval source

- **The tag moves to `agnijs-bc-6`.** Source text that came from a JavaScript string (eval, `Function`) can hold lone surrogates, which a Rust `str` cannot. The compiler now converts such source once (`agnijs_js_parser::source`): each lone surrogate stands as U+FFFD in the text and is listed, by byte offset, in a table that `SourceText` carries (`lone_surrogates`). Literal values and `Function.prototype.toString` put the surrogates back. The source table of the payload therefore gains, after each source's name and text, the count of that table and its entries (a `u32` offset and a `u16` code unit each). The layout changed, so `agnijs-bc-5` payloads are rejected with the usual format mismatch and the host recompiles from source. No release shipped `agnijs-bc-5`.
- **Source from the host has an empty table.** `compile_script` and `compile_module` take a `&str`, so the table of a host script is empty and costs four bytes per source. A container can still carry a non-empty one, since any code tree (eval code included) can be encoded.
- **The decoder verifies the table.** Entries must be in strictly increasing offset order, each unit must be a surrogate (U+D800 to U+DFFF), and each offset must name a U+FFFD of the text; anything else is `BytecodeCorrupt`, before any code runs.

## Addendum (TASK-100.31, 2026-11-09): `agnijs-bc-7` carries compiled regex programs

- **The tag moves to `agnijs-bc-7`.** The engine now compiles regular expressions with its own matchers (ADR 0013 addendum), and their compiled programs can be serialised (`agnijs_js_regex::Regex::program_bytes`). The payload body is now the tree's length (`u64`), the tree, and a regex section: a `u32` count, then for each distinct pattern and flags of a regex literal anywhere in the tree its pattern (`u32` unit count, UTF-16 units), its flags (one byte, in `dgimsuvy` bit order) and its program (`u32` length, bytes). The checksum covers the whole body. The layout changed, so `agnijs-bc-6` payloads are rejected with the usual format mismatch and the host recompiles from source. No release shipped `agnijs-bc-6`.
- **Loading seeds the regex cache.** `eval_bytecode` and bytecode module loads decode every program and put it in the VM's regex cache under its pattern and flags, so evaluating a literal from precompiled code neither parses nor compiles the pattern. A program does not depend on the matcher mode, so one container serves every `Host::regex_matcher` setting. The cache is shared by all code in the VM, so a program from a container also serves `new RegExp` with the same source and flags; like the rest of the payload, it is trusted as far as source would be.
- **The decoder verifies every program before anything runs.** A program is a versioned layout of LEB128 integers (`agnijs-js-regex/src/program.rs`). Decoding checks every index (character sets, literal strings, loops, backreference lists, capture groups, capture slots), every jump target, and the structure the backtracking compiler always produces: loops and lookarounds properly nested and entered only at their start, every jump forward except a loop's own back edge, one reading direction per lookaround, and a linear-time program whose thread table fits the compiler's limit. A verified program cannot index out of bounds or loop forever, and the matcher keeps a match's ranges well formed. A program that fails any check refuses the whole container as `BytecodeCorrupt`. A program that verifies but was altered can match the wrong strings, as altered instructions can compute the wrong values.
- **The program format has its own version byte** inside the payload, but it is bound to the container tag like everything else: a change to the program layout bumps the tag.
- **A build without the linear matcher** (the `linear` feature off) writes no linear-time program and, when loading one, skips it, so the pattern backtracks there as it would if it had been compiled in that build. A container written by such a build marks every pattern as ineligible for the linear matcher, so a build with it backtracks on those patterns too (with no step budget); hosts that precompile should build with the default features.
