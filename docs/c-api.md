# The AgniJS C API

`crates/agnijs-capi` exposes the engine interface (`agnijs-engine-api`, ADR 0006) to C, C++ and any language that can call C. It builds as a static library (`agnijs_capi.lib` / `libagnijs_capi.a`) and a shared library (`agnijs_capi.dll` / `libagnijs_capi.so` / `libagnijs_capi.dylib`). The header is [`crates/agnijs-capi/include/agnijs.h`](../crates/agnijs-capi/include/agnijs.h), generated by cbindgen and checked in. The design record is [ADR 0021](adr/0021-c-api-is-an-id-based-abi-that-never-panics.md).

```sh
cargo build --release -p agnijs-capi
cmake -S crates/agnijs-capi/c -B build/capi -DAGNIJS_LIB_DIR=$PWD/target/release
cmake --build build/capi --config Release
ctest --test-dir build/capi -C Release --output-on-failure
```

The CMake project builds the C test program (`c/tests/capi_test.c`) and two examples against both libraries:

- `c/examples/timers.c` is an event loop with `setTimeout` on a host timer queue, a virtual clock, and the job queue pumped between timers.
- `c/examples/classes.cpp` has RAII wrappers, a host class with a finalizer and prototype methods, and a JS constructor around a host factory.

When linking the static library, also link the system libraries the Rust standard library needs. They are listed in `c/CMakeLists.txt`, and `cargo rustc -p agnijs-capi --release -- --print native-static-libs` prints them for your target.

## A first program

```c
#include "agnijs.h"
#include <stdio.h>
#include <string.h>

int main(void) {
  AgnijsEngineOptions o;
  memset(&o, 0, sizeof o);            /* zero means "default" for every field */
  o.struct_size = (uint32_t)sizeof o; /* always */
  AgnijsEngine e = 0;
  if (agnijs_engine_new(&o, &e) != AGNIJS_OK) return 1;
  AgnijsRealm r = 0;
  agnijs_engine_main_realm(e, &r);

  const char src[] = "[1, 2, 3].map(x => x * 2).join()";
  AgnijsValue v = 0, s = 0;
  if (agnijs_eval_script(e, r, "main.js", 7, src, sizeof src - 1, &v) == AGNIJS_OK &&
      agnijs_to_string(e, r, v, &s) == AGNIJS_OK) {
    char text[64];
    size_t n = 0;
    if (agnijs_string_to_utf8(e, s, text, sizeof text, &n) == AGNIJS_OK) printf("%s\n", text); /* 2,4,6 */
  }
  agnijs_value_free(e, s);
  agnijs_value_free(e, v);
  agnijs_engine_free(e); /* frees everything the engine handed out */
  return 0;
}
```

## Status codes

Every function returns an `AgnijsStatus`. After any call, `agnijs_last_error` (copied into your buffer) and `agnijs_last_status` describe the most recent failure on the calling thread.

| Range | Meaning | Codes |
| --- | --- | --- |
| `0` | success | `AGNIJS_OK` |
| positive | an outcome of running JavaScript | `AGNIJS_EXCEPTION` (take it with `agnijs_take_exception`), `AGNIJS_INTERRUPTED`, `AGNIJS_OUT_OF_MEMORY` (the engine's memory limit), `AGNIJS_OUT_OF_FUEL` (the fuel budget, ABI 1.1) |
| negative | the call itself was wrong, or the library refused it | `NULL_POINTER`, `INVALID_ENGINE`, `WRONG_THREAD`, `INVALID_HANDLE`, `WRONG_ENGINE`, `INVALID_REALM`, `INVALID_ARGUMENT`, `INVALID_UTF8`, `TYPE_MISMATCH`, `BUSY`, `POISONED`, `PANIC`, `BYTECODE`, `HOST`, `ENGINE`, `UNSUPPORTED`, `BUFFER_TOO_SMALL`, `LIMIT`, `NOT_FOUND` |

No function writes its output on failure, and outputs are checked before any work is done, so a bad output pointer leaves no side effects.

## Ids and ownership

Everything the library hands out is a 64-bit id, and `0` is never valid. That covers engines, realms, values, buffers, classes and module-hook sinks. An id carries a kind tag, a generation and a slot index. It is checked on every use, so a freed id, a stale id (its slot reused), an id of another engine or another kind, or a random number is reported, never dereferenced. The engine part of an id is unique among the engines alive at the same time (TASK-103.40): an id of another live engine gives `AGNIJS_ERR_WRONG_ENGINE` however many engines the process has made. Ids of an engine that was freed are not guaranteed to stay foreign: after about a million later engines its tag can be reused, and a stale id is then checked against the new engine's slots like any other id, as a freed id or a random number would be. Do not keep ids past `agnijs_engine_free`.

- **Values.** Every function that outputs an `AgnijsValue` gives you a new reference. Free it with `agnijs_value_free`, and take another with `agnijs_value_dup`. A value keeps its JavaScript object alive across garbage collections until you free it. A value used after it is freed gives `AGNIJS_ERR_INVALID_HANDLE`, and freeing it twice gives the same error.
- **Buffers.** Bytecode images and exception text come back as an `AgnijsBuffer` the engine owns. `agnijs_buffer_data` borrows its bytes, which stay valid until `agnijs_buffer_free`.
- **Strings.** Strings come out by copying: `agnijs_string_to_utf8` and `agnijs_string_to_utf16` copy into memory you own, add a terminating zero, and report the length without it in `needed`. `AGNIJS_ERR_BUFFER_TOO_SMALL` still sets `needed`, so call once to size the buffer and once to fill it.
- **No allocation crosses the boundary.** You never free memory the library allocated, and it never frees yours.
- **Freeing an engine.** `agnijs_engine_free` frees the engine and every value, buffer and host object it handed out, running their finalizers. Ids from it are then invalid (`AGNIJS_ERR_INVALID_ENGINE`), never dangling.
- **Input text.** Input text is UTF-8 with an explicit length, and need not be NUL-terminated. Invalid UTF-8 is refused with `AGNIJS_ERR_INVALID_UTF8`. `agnijs_new_string_utf16` accepts any code units, lone surrogates included.
- **Input pointers.** Pointers you pass are checked for NULL, alignment and length overflow. NULL with length 0 is allowed. What cannot be checked is that a non-NULL pointer really covers `len` readable bytes: that is your contract, as in every C API.

## Versioned structs and the ABI

Each struct you pass in or get filled (`AgnijsEngineOptions`, `AgnijsException`, `AgnijsMemoryUsage`, `AgnijsClassDef`, `AgnijsCallInfo`) starts with `uint32_t struct_size`. Set it to `sizeof` the struct and zero every field you do not use, since zero always means the default.

- **Smaller sizes.** A smaller `struct_size` than the library knows is refused.
- **Larger sizes.** A larger one, from a program built against a newer header, is accepted when the extra bytes are all zero. That means the program left the newer fields at their defaults. Otherwise it is refused with a message to upgrade the library.
- **ABI version.** `agnijs_abi_version` returns `major << 16 | minor`. Check that its major matches `AGNIJS_ABI_VERSION_MAJOR` at start-up.

The policy for version 1.x:

- **Append only.** Functions, constants and struct fields are only ever added: fields at the end of a struct, bumping the minor version. Nothing is reordered, removed or retyped, and the meaning of an existing status code does not change.
- **Breaking changes.** A breaking change bumps the major version. The library refuses a struct it cannot interpret rather than guessing at it.
- **Header drift.** The header is generated (`cbindgen --config crates/agnijs-capi/cbindgen.toml --crate agnijs-capi --output crates/agnijs-capi/include/agnijs.h`). CI regenerates it and fails on any difference, so the checked-in header always matches the library.

## Threads

An engine belongs to the thread that created it. A call from any other thread returns `AGNIJS_ERR_WRONG_THREAD`. Engines on different threads are fully independent. The one function callable from any thread is `agnijs_engine_request_interrupt`: the next interrupt poll stops the running script with `AGNIJS_INTERRUPTED`.

## Callbacks and reentrancy

You provide host functions (`agnijs_new_function`), host-object finalizers (`agnijs_register_class`) and hooks (`AgnijsEngineOptions`):

- interrupt
- console
- module resolve and load
- `import.meta`
- promise rejection
- clock

Every callback is called as `extern "C-unwind"`.

- **Hooks that receive the engine may call back into it.** These are host functions, the `import.meta` hook and the rejection hook. Nesting is capped at `max_reentrancy` (default `AGNIJS_DEFAULT_MAX_REENTRANCY` = 32, at most 256). Past the cap a call gets `AGNIJS_ERR_LIMIT`.
- **Hooks that receive no engine must not call into it.** These are module resolution and loading, console, interrupt, the clock and finalizers. Doing so gets `AGNIJS_ERR_BUSY`, as does `agnijs_engine_free` on an engine from inside its own callback. Module hooks answer through their sink: `agnijs_sink_set_string`, `agnijs_sink_set_module` or `agnijs_sink_set_error`.
- **What a host function returns.** It returns `AGNIJS_OK` with `*result` set; leaving it unset gives `undefined`. To throw, call `agnijs_throw(e, value)` and return `AGNIJS_EXCEPTION`. Returning the `AGNIJS_EXCEPTION` a nested call gave you passes that exception on. Returning any negative status becomes a JavaScript `Error` naming the status and message. `AGNIJS_INTERRUPTED`, `AGNIJS_OUT_OF_MEMORY` and `AGNIJS_OUT_OF_FUEL` propagate as themselves.
- **Argument handles.** The `this` and argument values in `AgnijsCallInfo` are valid only during the call. Use `agnijs_value_dup` on any you keep, as `setTimeout` does in `timers.c`.
- **Host functions are not constructors in ABI 1.0.** `new f()` throws a `TypeError`, and `AgnijsCallInfo.new_target` is always 0. Give a host class a constructor by wrapping a host factory in a JS function, as `classes.cpp` does.
- **Exceptions and unwinding.** A C++ exception must not leave a callback. Catch everything and turn it into `agnijs_throw` or a status, as the wrappers in `classes.cpp` do. A Rust panic unwinding out of a callback written in Rust is caught and reported.
- **When finalizers run.** Finalizers of host objects and host functions run after the object is collected, when the engine next drains its job queue (`agnijs_run_jobs`), or at `agnijs_engine_free`. They receive only their `void *` and must not call into the engine.

## Errors and exceptions

`AGNIJS_EXCEPTION` means a JavaScript exception is pending. `agnijs_take_exception` fills an `AgnijsException` with:

- the thrown value
- the name, message and stack text, as buffers
- the stack frame count

Free the three buffers and the value when you are done. The next API call that runs JavaScript replaces an exception you did not take.

The stack text is `Error.stack` in the V8 format (`    at f (file:line:column)` lines, ADR 0024).

**Source maps (ABI 1.2).** `agnijs_set_source_map(e, name, name_len, map, map_len)` registers a Source Map v3 for a script or module name. Positions in `Error.stack`, call sites and the exception's stack text then refer to the original source. Pass a NULL `map` to remove it. A module load hook can instead hand the map over with the module: call `agnijs_sink_set_source_map(sink, map, len)` alongside `agnijs_sink_set_string`. A map that does not decode is ignored, and positions stay generated; hostile maps never crash the engine.

## Memory, interrupts and the stack

For what these limits do and do not cover when the script is hostile, see [security-model.md](security-model.md).

- **Memory limit.** `memory_limit` (or `agnijs_set_memory_limit`) caps the heap. Running past it ends the script with `AGNIJS_OUT_OF_MEMORY`, which JavaScript cannot catch, and the engine stays usable. The limit counts objects and their properties and elements, strings, ArrayBuffer and SharedArrayBuffer stores, and the entries of Map, Set, WeakMap and WeakSet; `agnijs_memory_usage` reports the same `heap_bytes`. A built-in that would allocate a large block (a buffer, `repeat`, `padStart`, `padEnd`, `join`, a long concatenation) checks the limit first and returns `AGNIJS_OUT_OF_MEMORY` without allocating it. The count is approximate, so set the limit well below what the process can afford.
- **Interrupts.** The `interrupt` hook is polled while JavaScript runs, including inside regex matches and native built-ins that loop over their input; return nonzero to stop with `AGNIJS_INTERRUPTED`. `agnijs_engine_request_interrupt` does the same from any thread.
- **Stack budget.** Every call runs under a native stack budget (`stack_budget`, default `AGNIJS_DEFAULT_STACK_BUDGET` = 512 KiB, minimum `AGNIJS_MIN_STACK_BUDGET` = 64 KiB). Deeply nested source, deep JSON, proxy chains and deep native recursion fail with a `SyntaxError` or `RangeError` "Maximum call stack size exceeded" instead of overflowing your thread's stack.
  - **Headroom.** Keep `AGNIJS_STACK_HEADROOM` (256 KiB) free beyond the budget on the calling thread, because the library may run that far past the budget before noticing.
  - **Platform defaults.** The default budget suits a main thread or a 1 MiB thread. macOS secondary threads default to 512 KiB, so give them a smaller budget or a larger stack.
  - **Depth.** The depth a budget allows depends on the build: release frames are much smaller than debug ones.
  - **Nesting.** A reentrant call keeps the outer, tighter limit.
- **Fuel (ABI 1.1).** `agnijs_set_fuel(e, n)` lets JavaScript run `n` more bytecode instructions, counted across every realm and inside host callbacks. When none is left the running call returns `AGNIJS_OUT_OF_FUEL`, which JavaScript cannot catch (no `finally` runs), and every later call returns it too until the host sets a new budget or calls `agnijs_clear_fuel`. `agnijs_get_fuel` reads what is left (`AGNIJS_ERR_NOT_FOUND` when no budget is set), so a host meters one call by setting a budget before it and reading the rest after; to meter a realm on its own, give it its own engine. The count depends only on the script and the library version, so exhaustion comes at the same instruction on every run and platform. Fuel counts bytecode only: a native built-in costs the instruction that calls it, however much work it does (a regex match, a join, a sort). Bound that work with the interrupt hook, which the regex matchers and native loops poll, and the memory limit. While a budget is set the JIT does not run, and a budget makes the interpreter about 1.6x slower; without one it costs nothing.
- **Deterministic runs (ABI 1.1).** `agnijs_set_random_seed(e, seed)` seeds `Math.random` (any value, zero included; calling it again restarts the sequence). With a seed, the `now_ms` hook returning fixed times, and fuel instead of the interrupt hook, a program gives the same output on every run and platform. The C API's time zone is always UTC and its locale `en-US`. `docs/determinism.md` lists what can still vary.

## What never happens, and what still can

**No function panics or aborts the process.**

- **Every exported function runs under `catch_unwind`.** A caught panic returns `AGNIJS_ERR_PANIC`. It also poisons the engine it happened in: later calls give `AGNIJS_ERR_POISONED`, and `agnijs_engine_free` stays safe.
- **The crate denies the operations that can panic or truncate.** Clippy forbids `unwrap`, `expect`, indexing, slicing, unchecked arithmetic and truncating casts.
- **It refuses to build with `panic=abort`.**

The paths that can still end the process are outside the library's control:

- **System allocation failure.** Rust's allocator aborts when the operating system refuses memory. The engine's own memory limit is checked well before that, so set one for untrusted code.
- **A stack overflow below the budget.** This happens if your thread has less than budget plus headroom free when it calls in.
- **Broken caller contracts.** A pointer that does not cover the length you pass, or a callback that unwinds a C++ exception, is undefined behaviour on your side of the boundary.

## Testing

The capi crate's own tests cover:

- **Behaviour** (`tests/basics.rs`): realms, scripts, modules and their hooks, values, calls, host functions and objects, exceptions with stacks, promises and jobs, memory limits and interrupts.
- **Hostile inputs** (`tests/hostile.rs`): null, stale, foreign and forged ids; double frees; use after engine free; wrong thread; invalid UTF-8 and UTF-16; length overflow; misbehaving callbacks; reentrancy limits; deep nesting on a small stack.
- **Fault injection** (`tests/fault_injection.rs`, `--features fault-injection`): panics at chosen points, poisoning and recovery.
- **Bounded fuzzing** (`tests/fuzz.rs`):
  - random call sequences, checking statuses and the handle count
  - mutated scripts, differentially against the Rust engine
  - mutated bytecode
  - `AGNIJS_CAPI_FUZZ_ITERS` scales the work and `AGNIJS_CAPI_FUZZ_SEED` picks the seed.
- **The C test program**, run under AddressSanitizer and LeakSanitizer in CI.
- **Miri**: `miri_` unit tests over the raw-pointer helpers and the handle table.
- **GC stress**: the behaviour and hostile suites under a collection at every safe point.
